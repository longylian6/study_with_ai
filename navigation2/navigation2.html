    从导航目标到机器人运动

    参考：Nav2 Rolling · Navigation Concepts ↗

    Navigation2（Nav2）是 ROS 2 的移动机器人导航框架：它把任务编排、路径规划、运动控制与环境感知组织成可协作的模块。先理解各模块解决什么问题，再进入 package 和算法实现。

    1. 1. 接收目标应用通过 Action 发起导航
    2. 2. 编排任务行为树协调规划、跟踪与恢复
    3. 3. 计算路径规划器求路，按需平滑路径
    4. 4. 跟踪运动控制器持续计算运动指令

    定位与 TF 提供“我在哪里”，环境表示提供“周围哪里能走”。上图是典型协作过程的简化示意；实际执行顺序、重规划和恢复策略由行为树配置决定。

    01 · ROS 2 通信与生命周期 ROS 2

    Action：管理持续一段时间的任务

    客户端发送目标，服务端执行任务、反馈进度并返回结果。导航应用通过 NavigateToPose 调用 BT Navigator，行为树再调用规划、控制等 Action。

    Lifecycle 与 Bond：管理运行状态

    节点先配置，再激活执行；停用和清理也有明确阶段。Lifecycle Manager 协调状态转换，Bond 监测节点存活，故障时协调整个系统停用。

    常见启动过程：未配置 → 配置 → 未激活 → 激活 → 运行。

    02 · 行为树：安排任务如何执行 Behavior Trees

    行为树把导航流程组合成可复用的任务节点。它负责决定何时规划、跟踪、重试或恢复；具体路径和运动指令由相应服务器计算。

    Nav2 使用 BehaviorTree.CPP，在 BT Navigator 中加载节点插件，并通过 XML 描述树结构。修改任务流程时，可以组合节点或子树。

    例如：计算路径 → 跟踪路径；遇到失败时，按树中定义的条件尝试恢复，再重新执行任务。

    03 · 导航服务器与算法插件 Navigation Servers

    服务器提供任务接口并管理运行资源；插件实现具体算法。配置中的插件名称让任务选择所需算法，例如由 Controller Server 调用 DWB 控制插件。

    职责 / package解决的问题典型 Action
    规划 · nav2_planner从当前位置到目标，计算可行路径。ComputePathToPose
    控制 · nav2_controller结合局部环境，计算跟踪路径的运动指令。FollowPath
    平滑 · nav2_smoother改善已有路径的折角或其他几何质量。SmoothPath
    行为 · nav2_behaviors执行旋转、后退、等待等任务；各插件提供自己的 Action。Spin、BackUp、Wait
    路网 · nav2_route在预定义节点与有向边组成的路网上选择路线。ComputeRoute、ComputeAndTrackRoute

    航点跟随由 nav2_waypoint_follower 组织多个目的地，并可在到达时执行拍照、等待等任务。

    04 · 状态估计：机器人在哪里 State Estimation

    导航需要随时间更新的位置与姿态。全局定位校正漂移，里程计提供局部连续的运动估计，TF2 连接各坐标系。

    map → odom → base_link → 传感器坐标系

    map → odom 通常由定位或 SLAM 提供；odom → base_link 由里程计系统提供。

    AMCL 在已有地图上定位；SLAM 同时建图与定位。轮编码器、IMU、视觉等数据可融合为里程计；外部项目 robot_localization 常用于此。

    05 · 环境表示：周围哪里能走 Environmental Representation

    代价地图（Costmap）用二维栅格表达空闲、障碍、未知和膨胀代价，为规划、控制和行为提供环境信息。

    多个图层插件把地图、传感器观测等信息合入代价地图。过滤器则利用区域掩码表达禁行、限速等空间规则。

    机器人接近障碍时，周边膨胀代价会影响路径选择；进入限速区域时，区域规则可约束速度。理解这些输入，有助于判断导航行为是否符合预期。

            ROS 2 基础

            QoS发布者与订阅者的通信规则
            它解决什么问题
            QoS（Quality of Service）规定消息怎样传输和保留。发布者与订阅者的策略需要兼容，否则即使 Topic 名称和消息类型相同，也可能无法建立通信。
            Reliability
            Reliable 尽力保证消息送达，适合地图、规划结果等重要数据；Best Effort 允许丢失少量消息，适合频率高、下一帧很快到来的传感器数据。
            Durability
            Volatile 只接收订阅建立后的新消息；Transient Local 允许新订阅者取得发布者保留的历史消息，常用于地图等需要“后加入也能立即获得”的数据。
            History 与 Depth
            Keep Last 只保留最近若干条消息，depth 指定队列长度。队列过小可能覆盖尚未处理的消息，过大会增加内存占用和延迟。

            ROS 2 常用 QoS 配置

            QoS Profile用途ReliabilityDurabilityHistory (Depth)
            Default QoS默认 TopicReliableVolatileKeep Last (10)
            Sensor Data QoS传感器数据Best EffortVolatileKeep Last (5)
            Services QoSServiceReliableVolatileKeep Last (10)
            Parameters QoS参数ReliableVolatileKeep Last (1000)

            这些是 ROS 2 的常用预设。实际通信还要求发布端与订阅端的策略兼容；使用 System Default 时，具体值由底层中间件决定。

            nav2_voxel_grid 是 Nav2 中紧凑、快速的三维体素栅格基础库。它把空间切成一个个小立方体（voxel），记录每个体素是空闲、未知还是被障碍物占用。主要使用者是 nav2_costmap_2d 中的 VoxelLayer。

            分类位置：算法组 → nav2::LifecycleNode → 不带 Action Server → nav2_costmap_2d 的体素层基础库。nav2_voxel_grid 本身不是 LifecycleNode，也不是插件或 Action Server；插件类 VoxelLayer 位于 nav2_costmap_2d。README ↗ · package.xml ↗

            解决什么问题

            普通二维代价地图只能说明某个地面格子是否有障碍。体素栅格在同一个 (x, y) 位置沿高度方向增加多个 z 层，因此可以保存激光雷达或深度相机看到的三维障碍。

            例如传感器看到桌面时，体素层可以在桌面高度标记障碍；传感器射线穿过的空间则可以被清除为空闲。

            它在 Nav2 中的位置

            nav2_voxel_grid::VoxelGrid 只负责存储和计算。VoxelLayer 负责接收传感器数据、坐标变换、参数配置，并把三维结果投影到二维 costmap，供规划器和控制器避障。

            开启 publish_voxel_map 后，也是 VoxelLayer 将内部数据包装成 nav2_msgs/msg/VoxelGrid 并发布；消息定义并不属于本包。

            VoxelLayer 类 ↗ · VoxelLayer 实现 ↗

            核心设计：一个 32 位整数表示一整列体素

            网格在 x × y 平面上为每一列保存一个 uint32_t。每个高度层使用两个对应的 bit，最多表示 16 个 z 层。两个 bit 的组合表示三种状态：

            位组合VoxelStatus简单含义
            00FREE射线已经确认这里没有障碍。
            01UNKNOWN还没有足够观测；网格初始化和 reset 后均为此状态。
            11MARKED传感器观测到障碍，体素已被标记。

            这种表示只为每个二维格子分配 4 字节，状态判断可以使用位运算，速度接近二维栅格；代价是高度最多 16 层。构造或 resize 时传入更大的 size_z，实现会将其限制为 16。

            主要接口

            接口作用典型用途
            markVoxel() / clearVoxel()标记或清除一个体素。处理单个障碍观测。
            markVoxelLine()沿三维线段标记经过的体素。需要把一段空间标为占用时使用。
            clearVoxelLine()用三维 Bresenham 射线清除一条线上的体素，可限制起止距离。根据传感器视线清除已不再存在的障碍。
            clearVoxelLineInMap()清除射线，同时依据列中的未知和已标记数量更新二维 costmap。VoxelLayer 将三维清除结果同步投影到二维地图。
            getVoxel()读取某个 (x, y, z) 体素的三状态。查询和可视化单个体素。
            getVoxelColumn()按阈值把一整列归纳为 MARKED、UNKNOWN 或 FREE。把三维信息压缩为二维占用结果。
            resize() / reset()调整网格或把全部体素恢复为未知。地图尺寸变化或重新初始化。

            一次障碍更新如何流动

            1. VoxelLayer 接收 PointCloud2 或 LaserScan 等障碍观测，并将点转换到 costmap 坐标系。
            2. 障碍点对应的体素被标记为 MARKED。
            3. 从传感器原点到观测点的射线用于清除可见的空闲体素。
            4. 每个体素列按 mark_threshold 和 unknown_threshold 投影到二维 costmap。
            5. 二维 costmap 最终供规划、控制和碰撞检查使用；需要调试时还可发布 VoxelGrid 消息。

            3 · Launch 工具：启动时处理参数

            这些工具从 nav2_common.launch 导入。它们在 Launch 解析上下文时计算结果，比如输出临时参数文件的路径，或判断是否包含某个节点的配置。

            工具简单理解当前仓库的使用
            RewrittenYaml读取 YAML，按参数名或路径修改值，也支持替换键、替换值、添加根键；写入临时文件，返回新文件路径，保留原文件。nav2_bringup 为参数加入命名空间、改写 autostart 等；nav2_map_server 的矢量对象启动文件，以及系统测试、对接测试也使用它。
            ReplaceString按文本替换文件中的字符串并生成临时文件；支持条件，条件不满足时返回原文件路径。当前仓库提供并导出此工具，但未发现实际调用；navigation_launch.py 中仅有提及旧版本用法的注释。
            LaunchConfigAsBool把启动参数统一为字符串 'True' 或 'False'。忽略大小写和首尾空白，true、1、yes、on 被视为真，其余为假。nav2_bringup 用它处理 use_sim_time、autostart、use_composition 等开关。返回的是字符串，不是 Python bool。
            HasNodeParams检查 YAML 顶层是否有指定节点名的键，返回字符串 'True' 或 'False'。nav2_bringup 的 slam_launch.py 检查是否存在 slam_toolbox 配置，再决定传入用户参数文件还是沿用其默认配置。

            HasNodeParams 检查的是文件内容，不查询节点是否正在运行；也不会递归查找所有命名空间下的节点。

            一个容易理解的例子：启动时修改 autostart

            下面是 Launch 文件中的配置片段。节点收到参数时，RewrittenYaml 会生成一份修改后的临时 YAML；原来的 nav2_params.yaml 保持不变。

            from launch.substitutions import LaunchConfiguration
from nav2_common.launch import LaunchConfigAsBool, RewrittenYaml

configured_params = RewrittenYaml(
    source_file=LaunchConfiguration('params_file'),
    root_key=LaunchConfiguration('namespace'),
    param_rewrites={'autostart': LaunchConfigAsBool('autostart')},
    convert_types=True,
)
# 将 configured_params 用作节点参数文件。
# params_file、namespace、autostart 需要在 Launch 中声明。

            dwb_msgs：DWB 的轨迹、评分与调试接口

            它在 nav_2d_msgs 的二维速度之上，组织候选轨迹、单项评分、综合评分和整轮局部规划记录。可以把它理解为 DWB 的“候选轨迹与成绩单”数据格式；本包只生成接口类型，不运行节点。

            Topic 与消息 4 种

            四种消息逐层组合：Trajectory2D 表示候选轨迹，CriticScore 表示单项评分，TrajectoryScore 汇总一条轨迹，LocalPlanEvaluation 汇总一轮规划。

            用途依据当前仓库源码核对。接口清单 ↗

            Trajectory2D一个候选速度会形成的预测轨迹
            字段含义
            velocity 是候选速度指令；poses 是模型预测经过的位姿；time_offsets[i] 表示对应轨迹点相对模拟起点的时间。

            使用 package 与用途：dwb_plugins 生成轨迹；dwb_critics 检查障碍、路径偏离等代价；dwb_core 组织评估、选择和发布。

            Trajectory2D.msg ↗ · 轨迹生成源码 ↗

            完整原始定义（含字段类型、默认值与常量）

            # For a given velocity command, the poses that the robot will go to in the allotted time.

# Input Velocity
nav_2d_msgs/Twist2D velocity
# Time difference between first and last poses
builtin_interfaces/Duration[] time_offsets
# Poses the robot will go to, given our kinematic model
geometry_msgs/Pose[] poses
            CriticScore一个评分器对轨迹的评分
            字段含义
            name 是评分器名称；raw_score 是原始分数；scale 是权重。该评分器对总分的贡献为 raw_score × scale，DWB 中通常代价越低越好。

            使用 package 与用途：dwb_core 创建并填充消息；dwb_critics 的插件返回原始数值，再由 dwb_core 包装成 CriticScore。

            CriticScore.msg ↗ · 评分源码 ↗

            完整原始定义（含字段类型、默认值与常量）

            # The result from one critic scoring a Twist.
# Name of the critic
string name
# Score for the critic, not multiplied by the scale
float32 raw_score
# Scale for the critic, multiplied by the raw_score and added to the total score
float32 scale
            TrajectoryScore一条候选轨迹的完整成绩单
            字段含义
            traj 是被评估的轨迹；scores 保存各评分器结果；total 是已计算评分项的加权总代价。当前实现还用 total=-1 标记非法轨迹；提前结束评分时，scores 可能只包含部分评分项。

            使用 package 与用途：dwb_core 生成、比较并记录候选结果，选择总代价较低的合法轨迹；发布器读取分数为轨迹可视化着色。

            TrajectoryScore.msg ↗ · 候选比较源码 ↗

            完整原始定义（含字段类型、默认值与常量）

            # Complete scoring for a given twist.

# The trajectory being scored
Trajectory2D traj
# The Scores for each of the critics employed
CriticScore[] scores
# Convenience member that totals the critic scores
float32 total
            LocalPlanEvaluation一轮局部规划的全部候选记录
            字段含义
            header 保存时间和坐标系；twists 虽然名字是速度，元素实际是 TrajectoryScore；best_index / worst_index 是最佳和最差合法轨迹在数组中的下标。

            使用 package 与用途：dwb_core 按配置和订阅情况发布 evaluation，并把评估结果转换为轨迹可视化标记。

            LocalPlanEvaluation.msg ↗ · 发布源码 ↗

            完整原始定义（含字段类型、默认值与常量）

# Header, used for timestamp
std_msgs/Header header
# All the trajectories evaluated and their scores
TrajectoryScore[] twists
# Convenience index of the best (lowest) score in the twists array
uint16 best_index
# Convenience index of the worst (highest) score in the twists array. Useful for scaling.
uint16 worst_index
